# ⚙️ Конфигурация: Пульт управления

Ты уже запустил бота, и он работает. Но настоящий мастер не полагается на настройки "по умолчанию".

Файл `application.yml` — это **кокпит твоего бота**. Отсюда ты управляешь его поведением, скоростью реакции и памятью. Давай разберем, что там можно (и нужно) крутить.

## 🔑 База: Токен и Имя

Самое важное. Без этого бот даже не проснется.

```yaml
nyagram:
  bot-token: "123456789:ABC..." # Твой секретный ключ
  bot-username: "MyCoolBot"     # Имя без @
```

> ⚠️ **СОВЕТ БЕЗОПАСНОСТИ:**
> Никогда не пиши токен прямо в файл, если собираешься выкладывать код на GitHub! Злые хакеры (или добрые сканеры) украдут его за секунду.
>
> Делай так:
> ```yaml
> nyagram:
>   bot-token: ${BOT_TOKEN} 
> ```
> А сам токен задавай в переменных окружения (Environment Variables) на сервере или в настройках запуска IDEA.

## 📡 Режимы работы: Polling vs Webhook

Nyagram умеет работать в двух режимах. Это как два способа узнать, пришла ли почта.

### 1. POLLING (Опрос) — Для старта и тестов 🏃‍♂️
Бот сам постоянно "стучится" к серверам Telegram и спрашивает: *"Есть новые сообщения? А сейчас? А сейчас?"*.

*   **Плюсы:** Работает везде, даже с твоего ноутбука за NAT-ом (роутером). Не нужен домен и HTTPS.
*   **Минусы:** Чуть медленнее реакция (задержка до 1-2 секунд), лишний трафик.

**Настройка:**
```yaml
nyagram:
  mode: POLLING
  long-polling-timeout-seconds: 50 # Сколько секунд ждать ответа от сервера (лучше не трогать)
```

### 2. WEBHOOK (Вебхук) — Для продакшена ⚡️
Telegram сам "стучится" к твоему боту, как только юзер что-то написал.

*   **Плюсы:** Мгновенная реакция, экономия ресурсов.
*   **Минусы:** Нужен "белый" IP или домен, обязателен SSL-сертификат (HTTPS).

**Настройка:**
```yaml
nyagram:
  mode: WEBHOOK
  webhook-url: "https://my-domain.com" # Твой внешний адрес
  webhook-path: "/callback/telegram"   # Куда будут прилетать запросы
```

## 🚀 Производительность (Потоки)

Представь, что твой бот — это касса в супермаркете.
Параметр `worker-thread-count` — это количество кассиров.

*   Если кассир один (`1`), то пока он обслуживает одного покупателя (обрабатывает команду), остальные ждут в очереди.
*   Если кассиров много (`100`), очередь движется быстрее.

```yaml
nyagram:
  # Сколько команд бот может обрабатывать ОДНОВРЕМЕННО
  worker-thread-count: 10 
```

**Сколько ставить?**
*   Для простых ботов: 10-20 хватит с головой.
*   Для нагруженных: можно и 100-200 (Nyagram использует эффективные потоки, так что не бойся ставить больше).

## 🧠 Память (FSM и State)

Бот должен помнить, на каком шаге находится пользователь (например, "вводит адрес" или "выбирает пиццу"). Где хранить эту память?

```yaml
nyagram:
  state-repository:
    # memory - В оперативной памяти (быстро, но стирается при перезагрузке)
    # redis  - В базе данных Redis (надежно, переживет перезагрузку)
    # database - В обычной БД (SQL)
    type: memory 
```

### Настройки сессии (FSM)

```yaml
nyagram:
  fsm:
    ttl-minutes: 60 # Сколько минут помнить состояние, если юзер молчит
```
Если юзер начал оформлять заказ и ушел пить чай на 2 часа, бот "забудет" его состояние, чтобы не хранить мусор.

## 🕵️ Логирование

Хочешь видеть всё, что происходит? Настрой логи!
В `application.yml` (корневой уровень, не внутри `nyagram`):

```yaml
logging:
  level:
    # DEBUG - Видеть каждое входящее сообщение и действие
    # INFO  - Только важные события (запуск, ошибки)
    com.kaleert.nyagram: DEBUG 
```

## Полный пример (Copy-Paste)

Вот готовый конфиг для старта:

```yaml
server:
  port: 8080

nyagram:
  bot-token: ${BOT_TOKEN} # Берем из env
  bot-username: "MySuperBot"
  mode: POLLING
  
  worker-thread-count: 20
  
  state-repository:
    type: memory
    
  fsm:
    ttl-minutes: 30

logging:
  level:
    com.kaleert.nyagram: INFO
```

Теперь твой бот настроен как профессиональный инструмент!
