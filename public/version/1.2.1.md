# Nyagram v1.2.1

*Релиз: Июль 2026 | Telegram Bot API 10.1 & 10.2*

Это обновление делает Nyagram Java-фреймворком для Telegram с **нативной поддержкой Multi-Tenant SaaS-архитектуры**. Запуск нескольких ботов на одном Spring Boot приложении теперь доступен "из коробки".

### ✨ Что нового? (What's New)
*   **Multi-Bot Core (SaaS):** Внедрен интерфейс `NyagramBotProvider` и контекст `BotTokenContext`. Nyagram автоматически маршрутизирует вебхуки и подменяет токены "на лету" при ответах.
*   **Управление профилем бота:** Добавлены API-методы `SetMyName`, `SetMyDescription` и `SetMyShortDescription`. Настраивайте профили партнерских ботов прямо из кода.
*   **Обновление Telegram Stars (API 10.x):** 
    * Добавлен метод `GetMyStarBalance` для проверки баланса звезд бота.
    * Добавлено поле `paid_star_count` в `Message` для отслеживания стоимости входящих сообщений.
    * Поддержка платных подписок на каналы: `CreateChatSubscriptionInviteLink`.
*   **Message Effects:** Добавлена возможность прикреплять визуальные эффекты (огонь, конфетти) к отправляемым сообщениям через метод `withEffect(effectId)`.
*   **Expandable Blockquotes:** В `TextUtil` добавлены методы для генерации сворачиваемых цитат (Rich Text API).
*   **Продвинутые опросы (Polls):** Поддержка флага `allows_revoting` и нескольких правильных ответов (`correct_option_ids`) для викторин.

### 🛠 Улучшения (Improvements)
*   **Ребрендинг базового пакета:** Пакеты переведены на фирменный домен `pro.kaleert.*`.
*   **Умный FailureAnalyzer:** Встроен кастомный перехватчик фатальных ошибок Spring Boot, указывающий прямые ссылки на документацию при ошибках инициализации.
*   Улучшена работа `AutoMultipartBuilder` с большими файлами.

### 🐛 Исправления ошибок (Bug Fixes)
*   **Thread Context Leak (Critical):** Исправлен сброс `MDC` и `BotContextHolder` при асинхронном выполнении команд. `MiddlewareChain` больше не выбрасывает задачи в глобальный `ForkJoinPool`, сохраняя изоляцию потоков.
*   Исправлен баг, при котором `NyagramWebhookController` конфликтовал с кастомными путями в `application.yml`.
